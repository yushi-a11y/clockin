## 二、后续迭代建议（按优先级排序）

### P0 · 强烈建议下一轮做

1. **换班通知红点/待办中心**
   - 当前 `myPendingSwapCount` 已有角标，可扩展为"员工端总待办"（含 待确认换班 + 待审补卡 + 被强制下线未读原因）。
   - 顶部导航头像右上角小红点，hover 显示待办列表。

2. **密码找回/重置流程**
   - 密码框"忘记密码"链接 → 弹框填工号 → 写 `pwdReset` 请求 → 管理员后台"密码重置"面板一键重置为默认 `123456`。
   - 避免员工每次都得口头找管理员。

3. **员工侧"申请换班市场"**
   - 当前只能单向"转让"，不支持"我 7/23 的 10-11 换你 7/24 的 14-15"。
   - 新增 `swapMarket` config 行，每条记录是双向撮合请求；双方都点"接受"后自动互换。
   - 增加"时间窗"限制：只能转让本周或下周的班次（业务常见规则）。

### P1 · 架构升级

4. **RLS 精细化（`logs` 表）**
   - 当前 `using(true)/check(true)` 任何人都能删日志。
   - 改为：`check (current_user = 'admin_role')`，仅管理员可删改；普通员工只能 INSERT/SELECT。
   - 同时给 `logs` 加触发器，禁止 UPDATE（日志不可改）。

5. **多角色权限**
   - 当前只有"管理员 vs 员工"两种角色。
   - 引入 `roles` 表（id/name/permissions[]），`TEAM` 成员加 `roleId` 字段；后台登录时校验权限点（如"只能改自己部门的选班"）。

6. **数据表拆分**
   - 当前所有核心数据塞在 `config` 表的 10+ 行 JSON 里，每次 upsert 整包推送。
   - 拆成 `shifts/team/picks/selcfg/slotcap/swaps/forceout/logs/makeups` 独立表，按需订阅，性能上限更高。

7. **Supabase 初始化脚本**
   - 提供一键 SQL（含所有表结构 + RLS + 索引），新用户跑一次就能用，不再依赖口头告知。

### P2 · 锦上添花

8. **消息推送（换班/补卡/强制下线）**
   - 当前只能靠员工主动点进去看，无红点/弹窗/推送。
   - 可接 Supabase Edge Function + 钉钉机器人 webhook，关键事件推送到钉钉群。

9. **考勤 → 薪资对接**
   - 增加"算薪"面板：有效班次 × 单价 + 早补津贴 + 夜补津贴 - 迟到扣款 - 缺卡扣款 = 月薪预览。
   - 导出 CSV 给财务。

10. **离线模式指示**
    - 顶部同步徽标已有"离线"态，但员工不知道离线时打卡/选班会写到 localStorage 且可能丢。
    - 增加明确的"离线模式"横幅 + 待同步队列显示 + 上线后自动回放。

11. **数据备份/回滚**
    - 管理员后台"历史快照"按钮，每日自动备份 config/picks/logs 到独立表，支持一键回滚到昨日状态。

## 三、遗留技术债

1. **`confirmPwd` 的密码比对兼容分支较复杂**
   - `matched = (stored===inputVal) || (stored==null && inputVal==='123456') || (isHash(stored) && stored===inputHash)`
   - 老数据（明文 `123456`）走第二分支，老数据（其他明文）走第一分支（不安全），新数据（哈希）走第三分支。
   - 建议：首次登录成功后强制改密，把所有账号统一到哈希态；之后删掉第一、二分支。

2. **`forceout` 数据格式向后兼容代码**
   - `typeof fo==='number'` 判断兼容老格式。
   - 建议：跑一次迁移把所有老格式 `{mid: ts}` 升级成 `{mid: {ts, reason:''}}`，之后去掉兼容分支。

3. **`selCfg.retainDays` 默认值散落在多处**
   - `DEF_SELCFG.retainDays=60`、`prunePicks`、`pruneSwaps` 三处都写 `||60`。
   - 建议：统一抽 `getRetainDays()` 函数。

4. **`TEAM_SCHEMA_V` 迁移函数用 IIFE**
   - 启动时自动跑，对调试不友好。
   - 建议：改成显式 `runMigrations()` 函数，在 `initFBListeners` 之前调用，并在日志里打印迁移结果。

5. **`punches` 里混了 `makeup:true` 标记**
   - 正常打卡和补卡混在同一数组，导出/统计时如需区分会多一层 filter。
   - 建议：把 `makeups` 升级成独立表，punches 不再写 makeup 标记；补卡查询时 JOIN 或前端合并。
