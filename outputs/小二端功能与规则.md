# ClockIn 考勤系统 — 小二端（员工端）功能与规则总结

## 一、概述

小二端是 ClockIn 考勤打卡系统中面向一线员工的入口。员工通过浏览器打开系统后，选择自己的工号并验证密码，即可完成打卡、选班、查看选班情况、查看月度统计、申请换班/补卡/请假等操作。

本文档汇总小二端所有可见功能及其背后的业务规则，便于员工培训、操作参考和日常答疑。

## 二、账号绑定与登录

### 2.1 入口与设备绑定

1. 打开系统页面后，员工首先进入账号选择界面。
2. 系统会展示当前员工列表，员工点击自己的姓名/工号进行选择。
3. 首次选择或本地绑定已过期时，需要输入密码验证身份。
4. 验证通过后，系统会把当前设备与该工号绑定，并设置一个过期时间（默认到次日重置时间）。
5. 在绑定有效期内刷新页面或重新进入，系统会自动恢复登录状态，无需重复输密码。
6. 如果管理员在后台执行了"强制下线"，本地绑定会立即失效，员工需要重新验证密码。

### 2.2 密码规则

- 每个员工账号都有独立登录密码。
- 系统默认初始密码为 `123456`，首次登录后建议尽快修改。
- 密码在数据库中以 SHA-256 哈希形式存储，不保存明文。
- 员工可以在个人设置中自助修改密码：需要输入当前密码校验，新密码留空则重置为默认密码。
- 连续输错密码达到 5 次后，该账号会被锁定 30 秒，锁定期间无法继续尝试登录。

### 2.3 安全与限流

- 系统记录安全事件日志，包括登录失败、账号锁定、客户端时间漂移等。
- 客户端时间若与服务器时间偏差超过 5 分钟，会触发安全警告并记录。
- 系统对敏感接口做了操作限流，防止暴力破解和频繁提交。
- 小二端页面在移动端/触屏小尺寸设备上会被拦截，提示使用电脑浏览器访问。

## 三、页面总览

登录后，小二端顶部显示 7 个功能标签页：

| 标签页 | 说明 |
|--------|------|
| 打卡 | 查看当天班次、执行上班卡/下班卡打卡 |
| 选班 | 按周选择未来班次 |
| 选班情况 | 查看本周/本月选班统计和达标情况 |
| 月度 | 查看个人月度汇总、周有效班次、早补/夜补天数 |
| 换班 | 发起换班、确认他人发来的换班请求、查看历史 |
| 补卡 | 提交缺卡补卡申请、查看审批进度 |
| 请假 | 提交请假申请、查看审批进度 |

每个标签页右上角如有待处理事项（待确认换班、待审批补卡/请假），会显示红色数字角标。

## 四、打卡功能

### 4.1 打卡页展示内容

- 顶部显示当前问候语、实时时间、日期。
- 主体区域列出员工当天需要打卡的全部班次。
- 每个班次卡片显示：班次名称、上下班时间、状态标签、打卡按钮/已打卡时间。
- 可通过日期切换查看过去或未来某天的班次，但只能对符合规则的班次执行打卡。

### 4.2 上班卡与下班卡

每个班次都需要分别打上班卡和下班卡：

- **上班卡**：必须在班次开始时间前后指定的容忍窗口内打卡。
- **下班卡**：必须在班次结束时间前后指定的容忍窗口内打卡。
- 容忍窗口由系统后台配置的 `tolerance` 决定（单位：分钟）。
- 只有在窗口期内，"上班卡"/"下班卡"按钮才可用；提前或延后都无法打卡。

### 4.3 连班打卡规则

- 如果员工当天有多个连续衔接的班次，系统会把它们组成一条"连班链"。
- 每条连班链最多只包含 2 个班次：前一个班次的结束时间等于后一个班次的开始时间，才会被合并。
- 连班链的打卡逻辑：
  - 链中第一个班次的上班卡需要单独打。
  - 两个班次中间不需要打下班卡+上班卡，系统自动按链管理。
  - 链中最后一个班次的下班卡需要单独打。
- 这样设计的目的是避免员工点一次按钮就把多个连续班次全部打完，保证每个班次的起止都有明确记录。

### 4.4 打卡状态判定

系统根据当前时间与班次时间的关系，把每个班次显示为不同状态：

| 场景 | 状态说明 |
|------|----------|
| 今天的班次 | 按实际打卡情况显示"待上班"/"已上"/"待下班"/"已下"/"缺卡"等 |
| 历史班次 | 已过期的班次显示最终打卡结果，缺卡可发起补卡 |
| 未来班次 | 显示为"未开始"，不能提前打卡 |

### 4.5 提醒打卡

- 系统支持"打卡前 5 分钟提醒"功能。
- 员工可在打卡页开启或关闭提醒开关。
- 开启后：
  - 某个班次上班前 5 分钟内，如果还没打上班卡，会弹出浏览器通知和页面 Toast 提示。
  - 某个班次下班前 5 分钟内，如果还没打下班卡，会弹出下班提醒。
- 每条提醒每个班次每天只会触发一次，避免重复打扰。
- 如果浏览器未授权通知，系统会引导员工开启通知权限。

## 五、选班功能

### 5.1 入口与规则说明

进入"选班"标签页后，页面顶部会展示选班规则提示，员工可以看到当前可编辑的日期和已锁定日期。

### 5.2 选班开放时间

- 系统默认每周五 14:00 开放下一周期的选班。
- `openDay` 表示开放星期（0=周日，6=周六），`openHour` 表示开放小时。
- 在开放之前，员工只能查看排班表，不能选择或修改班次。
- 管理员可以在后台临时锁定选班，锁定后所有员工都无法编辑。

### 5.3 可编辑日期

- 员工只能编辑尚未到来的日期；过去日期不可修改。
- 一旦员工在某天保存了选班，该天会进入"已保存锁定"状态，员工自己不能再修改，只能通过换班或管理员后台调整。
- 管理员随时可以修改任何人的选班。

### 5.4 选班限制

- 每人每天最多选择 7 个时段。
- 每人每周（按周起始日计算）合计不超过 49 个时段。
- 同一时段每人每天只能占 1 个。
- 使用非本人工号或错误工号占位会被视为无效，系统会清除。

### 5.5 14:05 冻结与 14:10 补位

- 每周五 14:05 系统会冻结全表并清理超额班次：
  - 如果某天某人选班超过 7 个，超额部分会被标红并在冻结时清除。
  - 多占的时段必须在 14:05 前主动放出。
- 14:10 后：
  - 员工可以自由补位空余时段。
  - 请假、捡班、换班同样受"每天 7 个、每周 49 个"限制。

### 5.6 周最低有效

- 系统后台配置了 `minValid`（周最低有效班次），用于判定员工每周是否达标。
- 月度/选班情况页面会用绿色/红色标注每位员工每周有效班次是否达到该值。

## 六、选班情况

### 6.1 功能说明

"选班情况"标签页用于查看本人或全员的选班统计：

- 默认展示本周的实时计数表。
- 按周展示每个人每天的选班数量。
- 展示每人每周"有效合计"是否达标。
- 展示早补、夜补、月合计等关键指标。

### 6.2 有效合计计算规则

- 每日最多计 7 个有效班次。
- 每周最多计 49 个有效班次。
- 如果某天超过 7 个，只按 7 个计入有效；超出部分不计入。
- 如果某周超过 49 个，只按 49 个计入有效。

### 6.3 早补与夜补

- 早补：指员工选中特定早班时段（默认 ID 7，如 07:00-08:00）的天数。
- 夜补：指员工选中特定夜班时段（默认 ID 25，如次日 01:00-02:00）的天数。
- 这两个数值按实际选班数据自动统计，用于月度汇总。

## 七、月度统计

### 7.1 功能说明

"月度"标签页展示员工个人的月度汇总数据：

- 当前查看月份可通过左右切换。
- 展示当月各周的有效班次数量。
- 展示当月总有效班次、早补天数、夜补天数。
- 展示周达标情况。

### 7.2 达标判定

- 某周有效班次 ≥ 后台配置的 `minValid` 时，显示为"达标"。
- 未达标时显示为"未达标"，便于员工及时补班。
- 月度合计用于快速了解个人整月出勤强度。

## 八、换班功能

### 8.1 发起换班

- 员工在"换班"页选择日期、要转出的班次、接收人，然后提交换班请求。
- 只能转让自己已选中的班次。
- 换班受"每天 7 个、每周 49 个"限制：接收人接受后若超出限制，则无法成功。

### 8.2 换班状态

| 状态 | 含义 |
|------|------|
| pending | 等待对方确认 |
| accepted | 对方已同意，换班完成 |
| rejected | 对方已拒绝 |
| cancelled | 发起方已取消 |
| proxy_pending | 代提交，等待本人确认 |
| expired | 超过 48 小时未处理，自动过期 |
| approved | 管理员后台批准 |

### 8.3 待我确认

- 当其他员工把班次转给你时，会出现在"待我确认"列表。
- 你可以选择"同意"或"拒绝"。
- 超过 48 小时未处理，请求自动过期。

### 8.4 代提交换班

- 店长/管理人员可以在管理端替员工发起换班。
- 被代提交的员工会在"待我确认"中看到一条"代提交"请求，需要本人确认后才生效。

### 8.5 历史记录

- "我发起的换班"列表保留最近 20 条历史记录。
- 系统会自动清理过期太久的换班数据（默认保留 60 天）。

## 九、补卡功能

### 9.1 提交补卡申请

- 员工在"补卡"页选择缺卡日期、缺卡班次、实际打卡时间、填写原因后提交。
- 只能对已经过去的班次发起补卡。
- 提交后会生成一条待审批的补卡记录。

### 9.2 审批流程

- 补卡申请会实时同步到管理端的"补卡审批"页面。
- 管理员审批通过后，系统会自动写入一条打卡记录（标记为补卡）。
- 审批通过后，员工端该班次的"缺卡"状态会立即变为"已补"。
- 管理员也可以拒绝补卡申请，员工可查看拒绝原因。

### 9.3 状态查看

- 员工可以在补卡页查看自己所有补卡申请的状态：待审批、已通过、已拒绝。
- 待审批数量会在顶部标签角标中提醒。

## 十、请假功能

### 10.1 提交请假申请

- 员工在"请假"页选择请假日期、涉及班次、填写请假原因后提交。
- 提交后对应的班次会被标记为请假待审批状态。

### 10.2 审批流程

- 请假申请同步到管理端的"请假审批"页面。
- 管理员审批通过后，该日相关班次显示为"已请假"，不计入有效出勤。
- 管理员拒绝后，班次恢复正常选班状态。

### 10.3 代提交请假

- 店长/管理人员可以在管理端替员工提交请假。
- 代提交的请假申请同样需要经过审批流程。

### 10.4 状态查看

- 员工可在请假页查看所有请假记录及审批状态。
- 待审批数量会在顶部标签角标中提醒。

## 十一、数据同步与离线

- 系统使用 Supabase（PostgreSQL + Realtime）作为后端。
- 员工端数据会实时与云端同步，管理员在后台修改选班或审批补卡/请假后，员工端会立即更新。
- 当网络断开时，页面右上角会显示"离线"标识；恢复网络后自动重新连接。
- 员工本地有缓存，刷新页面后会先从本地恢复，再与云端同步。

## 十二、移动端拦截

- 为了保证打卡和选班体验，系统禁止在手机、平板等移动设备/触屏小屏设备上访问。
- 如果检测到用户代理（UA）为移动设备，或屏幕短边小于 1024px 且支持触控，会弹出拦截提示。
- 员工需要使用电脑浏览器访问系统。

## 十三、常见问题速查

**Q1：为什么我今天点了上班卡，系统也把下一个连续班次的卡打了？**
A：这通常发生在连班场景。系统把连续衔接的班次合并为一条链，链内中间不需要重复打卡。如果希望每个班次单独打卡，请确认班次之间没有连续衔接。

**Q2：为什么我想选某个班次点不了？**
A：可能原因：未到选班开放时间、选班被管理员锁定、该天已经保存锁定、已达每日 7 班/每周 49 班上限、该时段已被自己或他人占满。

**Q3：提醒打卡不弹出怎么办？**
A：请在浏览器地址栏左侧点击锁形/信息图标，允许本站发送通知；并确保打卡页的提醒开关已打开。

**Q4：我换班发给别人，对方多久不处理会过期？**
A：换班请求 48 小时未处理会自动过期。

**Q5：补卡申请提交后多久能看到结果？**
A：补卡需要管理员在管理端审批；审批通过后员工端会实时更新。

**Q6：密码输错几次会被锁？**
A：连续输错 5 次会锁定 30 秒。
