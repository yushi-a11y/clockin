# 首卡定位功能 · 上线 SQL（v2026.08.14.54）

在 Supabase → SQL Editor 执行这一条即可：

```sql
ALTER TABLE punches ADD COLUMN IF NOT EXISTS loc text;
```

## 说明

- 打卡记录的首卡定位以 `"纬度,经度,精度米数"`（如 `31.2304,121.4737,15`）文本形式写入 punches 表新列 `loc`。
- 灰度开关（总开关 + 按成员）存放在已有的 `config` 表，id 为 `loccfg`，**无需新建表**。
- 代码端已做降级保护：即使忘了先执行这条 SQL，打卡也不会失败（定位字段会被自动丢弃，打卡照常写入）。执行 SQL 后无需改代码即可开始记录定位。

## 关于 RLS（行级安全）—— 暂缓，单独处理

当前 punches/config 表的 RLS 策略是完全开放的（任何人拿 anon key 可读）。定位属于敏感数据，理论上应该收紧，但收紧 RLS 会影响补卡、备份写入等使用历史日期的写入路径，策略写错可能直接导致线上打卡失败。建议作为独立任务，在低峰期单独验证后再做，不在本次上线范围内。
