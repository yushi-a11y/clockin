# ClockIn FAQ 自助答疑助手部署指南

本指南说明如何把已完成的「小二端帮助中心 + 钉钉群聊机器人」功能正式接入 ClockIn 系统。

## 一、前置条件

- 已具备 ClockIn 项目的 Supabase 项目访问权限
- 本地已安装 Supabase CLI 并已登录 `supabase login`
- 钉钉群管理员权限，用于创建 outgoing 机器人
- 已确认 index.html 员工端「帮助」标签页代码已合并到生产分支

## 二、创建反馈数据表

在 Supabase SQL Editor 中执行以下 SQL：

```sql
-- ============================================================
-- faq_feedback：记录自助答疑未匹配或低置信度的问题
-- 供管理员定期 review 并扩充 FAQ 知识库
-- ============================================================

create table if not exists public.faq_feedback (
  id bigint generated by default as identity primary key,
  created_at timestamp with time zone default now(),
  ts bigint not null,
  question text not null,
  role text not null default 'employee',
  source text not null default 'help-center',
  member jsonb default null,
  handled boolean not null default false,
  notes text default null
);

alter table public.faq_feedback enable row level security;

create policy if not exists faq_feedback_insert_authenticated
  on public.faq_feedback
  for insert
  to authenticated
  with check (role = 'employee');

create policy if not exists faq_feedback_select_admin
  on public.faq_feedback
  for select
  to authenticated
  using (auth.role() = 'authenticated');

create index if not exists faq_feedback_handled_created_idx
  on public.faq_feedback (handled, created_at desc);
```

执行后可在 Table Editor 中确认 `faq_feedback` 表已生成，并建议为管理员账号配置 `select` 权限以便在后台查看未处理问题。

## 三、部署 Edge Function

Edge Function 文件位于本仓库 `outputs/cloud-sync/dingtalk-faq/index.ts`。

### 1. 复制到 Supabase 项目

将 `dingtalk-faq` 目录复制到 Supabase 项目的 `supabase/functions/` 下：

```bash
cp -r outputs/cloud-sync/dingtalk-faq /path/to/your/supabase-project/supabase/functions/
```

### 2. 确认环境变量

Edge Function 需要以下环境变量：

- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`

部署时 Supabase CLI 会自动注入项目对应变量，无需手动写入代码。

### 3. 部署

```bash
cd /path/to/your/supabase-project
supabase functions deploy dingtalk-faq --no-verify-jwt
```

部署成功后，Supabase Dashboard 的 Edge Functions 列表会显示 `dingtalk-faq`，并给出调用地址：

```
https://<project-ref>.supabase.co/functions/v1/dingtalk-faq
```

## 四、配置钉钉 outgoing 机器人

1. 进入目标钉钉群 → 群设置 → 智能群助手 → 添加机器人
2. 选择「自定义机器人」或「outgoing 机器人」
3. 机器人名称建议：`ClockIn 小二助手`
4. 在「消息接收地址」中填入上一步获取的 Edge Function URL：
   ```
   https://<project-ref>.supabase.co/functions/v1/dingtalk-faq
   ```
5. 勾选「@机器人」触发方式，保存

## 五、前端验证

员工端已内置「帮助」标签页。部署后让一名员工完成以下操作：

1. 登录 ClockIn 员工端
2. 点击底部「帮助」标签
3. 在搜索框输入「每天最多选几个班」，确认出现相关问题并点击展开答案
4. 输入无意义关键词如「abcdef」，确认出现「未找到相关问题」并点击「提交问题反馈」
5. 到 Supabase `faq_feedback` 表中确认新增一条 `source='help-center'` 的记录

## 六、钉钉机器人测试

在钉钉群中：

1. @ClockIn 小二助手 并提问：「怎么补卡」
2. 预期机器人回复包含「【补卡】怎么提交补卡？」的答案
3. 提问无意义内容如「今天的天气怎么样」
4. 预期机器人回复未命中提示，并告知已记录问题
5. 到 Supabase `faq_feedback` 表中确认新增一条 `source='dingtalk-bot'` 的记录

## 七、FAQ 知识库维护

当 `faq_feedback` 中积累未处理问题时，管理员应定期：

1. 在 Supabase Table Editor 中筛选 `handled = false`
2. 对有价值的问题，在 `index.html` 的 `FAQ_ENTRIES` 中新增条目
3. 同步更新 `supabase/functions/dingtalk-faq/index.ts` 中的 `FAQ_ENTRIES`
4. 重新部署 Edge Function
5. 将对应反馈记录的 `handled` 设为 `true`，并在 `notes` 中注明补充到哪个 FAQ

## 八、后续可选优化

- 在管理后台新增「未处理问题」页面，方便非技术人员直接查看和标记处理状态
- 对 FAQ 匹配阈值进行 A/B 测试，根据实际命中率调整 `0.25` / `0.28` 阈值
- 对高频问题增加快捷问题卡片，减少员工输入成本
