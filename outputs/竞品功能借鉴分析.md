# ClockIn 竞品功能借鉴分析

> 调研日期：2026-08-22 · 基于对国内外主流考勤/排班产品的真实功能调研
> 前提约束：ClockIn 是单文件 HTML + Supabase（免费档，**出口流量是瓶颈**），面向场馆兼职小时工，已有"抢班/换班/补卡/请假/绩效"等核心能力。
> 借鉴原则：**贴合场馆兼职场景、实现成本低、不加重出口流量负担**。

## 一、调研对象与核心发现

| 产品 | 定位 | 调研到的代表性功能 |
|---|---|---|
| 钉钉考勤 | 通用办公考勤 | WiFi/GPS/人脸识别打卡、外勤打卡 |
| 企业微信考勤 | 通用办公考勤 | 微信内打卡、外勤定位、请假/加班审批衔接 |
| Moka / 盖雅工场 | 专业 HR 考勤 | 一体化数据、复杂排班、AI 智能排班、异常自动审批、加班倍率、合规预警 |
| Factorial | 一体化 HR | 换班申请-审批自动更新、开放班次、冲突提醒、地理围栏 |
| Deputy | 排班+工时 | 换班/开放班次、**加班提醒**、**人工成本追踪**、排班模板、任务管理 |
| When I Work | 轻量排班 | 换班/放班、经理审批、开放班次管理、团队消息 |
| Homebase | 排班+招聘 | 找替班/换班/领取开放班次、覆盖确认、招聘入职 |
| 7shifts | 餐饮小时工 | **Availability 可用性声明**、**Shift Pool 班次池/抢班**、可靠性评分 |

盖雅工场把自动排班系统的价值总结为四大核心：**开放班次（零工抢单）、推荐人员（合规筛选）、一键排班、人力共享**。其中"推荐人员"会按出勤/技能筛选，并主动**拦截违规排班**（如"某人一周排班已超 48 小时"）。

## 二、竞品普遍有、ClockIn 还没有、且值得借鉴的功能

按"价值×契合度 / 实现成本"排序，分三档。

> **已有能力 vs 真实缺口**（2026-08-22 代码核实）：ClockIn 已具备自动工时统计（calcMonthMetrics 按打卡计入排班时长，管理端绩效表含工时列）、员工月度统计（早补/夜补/有效合计/有排班天数）、绩效录入与 OCR 导入、请假、双向换班、时段人数一键部署。因此下列推荐的真实缺口是：工资预估缺"时薪×倍率"这半程（工时数据已有）；合规工时提醒、候补队列、可用性声明为完全空白（关键词检索零结果）。另：Deputy 式"整表排班模板"不适用本产品——班次为固定整点时段、员工抢班制，管理员仅配置人数，故已从建议中移除。

### ⭐ 第一梯队：强烈建议（低成本、高契合、几乎不增加流量）

1. **候补/候补队列（开放班次 Waitlist）**
   来源：盖雅"开放班次+零工抢单"、7shifts Shift Pool、Homebase"领取开放工作"。
   现状：ClockIn 已有"抢班"，但班次抢满后其他人就没事可做了。
   借鉴：允许员工对已满班次"加入候补"，一旦有人取消自动按序顶替或推送提醒。场馆抢班场景天然契合，是对现有抢班的最小增量。

2. **可用性声明（Availability）**
   来源：7shifts 核心功能。
   现状：ClockIn 有"请假"（被动说某天不能来），但没有"我本周哪些时段可用"的主动声明。
   借鉴：员工提前声明可用时段，管理员排班/审批抢班时优先匹配可用者。兼职排班的刚需，纯前端表单 + 一张表即可。

3. ~~**合规提醒：连续工时 / 加班上限**~~（已撤销，2026-08-22 代码核实）
   ClockIn 已有同等甚至更强的能力：每天最多 7 个时段（MAX_PER_DAY=7，前端拦截 + 服务器端 atomicAddPickCap 双重校验）、每周最多 49 个时段（MAX_PER_WEEK=49，抢班/换班接收/批量保存均校验，另有周五冻结自动清超额），与盖雅"拦截一周超 48h"属同类能力。唯一残留缺口是"休息间隔检查"（如凌晨 02:00 下班后抢同日 07:00 班仅隔 5 小时无提示），但每日总量已封顶，风险有限，不单独立项。

4. **工资/工时预估（Pay Estimation）**
   来源：Deputy"人工成本追踪"、加班倍率（工作日/周末/法定假日）。
   现状：ClockIn 有绩效/出勤统计，但没有"钱"。
   借鉴：配置小时单价（可分工作日/周末倍率），在"我的绩效"页展示本月预计工时与预估工资。**数据已存在，纯前端计算**。对兼职者是最直接的激励，粘性极高。

### 🔶 第二梯队：有价值，需评估（中等成本）

5. **缺员一键广播补位（Open Shift Broadcast）**
   来源：盖雅"快速补位"。现状：有人取消后，缺口靠管理员人工发现。借鉴：出现空缺时一键推送给所有符合资格者，先到先得（走 Realtime，不新增轮询）。

6. **防作弊打卡增强（定位/WiFi）**
   来源：钉钉 WiFi/GPS 打卡。现状：ClockIn 靠设备指纹绑定防代打。借鉴：场馆地点固定，可加"仅场馆 WiFi 下可打卡"（校验 SSID，**不耗流量**）。GPS 需第三方地图、收益有限，暂不做。

### 🔴 第三梯队：不建议（高成本 / 低契合）

8. **拍照/人脸识别打卡** —— 钉钉有，但照片上传直接消耗 Supabase 出口流量，与当前"省流量"目标冲突，不做。
9. **AI 智能排班** —— Moka/盖雅卖点，但场馆几十人规模、且已是"员工抢班"模式，AI 排班投入产出比低，不做。
10. **团队消息/社交、招聘入职** —— When I Work / Homebase 的功能，已有微信群/线下流程，重复造轮子，不做。

## 三、落地建议（若开工，按此顺序）

1. **候补队列** —— 唯一完全空白且高频痛点（热门时段抢满后名额浪费），优先做。
2. **可用性声明** —— 完全空白，兼职排班刚需，随后做。
3. **工资预估** —— 工时统计已有，只差"时薪×倍率→预计收入"这半程。**注意：若工资实际按绩效系数结算而非纯时薪，此项价值会打折扣，需先确认结算方式。**
4. ~~合规工时提醒~~ —— 已由现有"每天 7 个/每周 49 个"硬性上限覆盖，不做。
5. 其余按需求反馈再定。

> 说明：以上竞品功能均来自真实页面调研；"对 ClockIn 的适配判断与实现成本"是我的设计评估，落地前可再逐项拆解。
